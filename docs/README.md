# Documentação do Ordum

O grupo escolheu construir um controle de finanças pessoais para aprender com um projeto de ponta a ponta. A primeira versão será um MVP; contas individuais, autenticação, privacidade e funcionalidades financeiras mais completas serão evoluções posteriores.

## Ordem de leitura

1. [Escopo do MVP](ESCOPO.md): objetivo, público e funcionalidades.
2. [Regras de negócio](REGRAS_DO_NEGOCIO.md): comportamento financeiro esperado.
3. [Arquitetura e ambiente](ARQUITETURA.md): tecnologias, organização e API planejada.
4. [Plano de desenvolvimento](PLANO_DE_DESENVOLVIMENTO.md): sequência de entregas.
5. [Validação](VALIDACAO.md): critérios e cenários de teste.
6. [Decisões e pendências](DECISOES.md): escolhas confirmadas e detalhes ainda sujeitos à revisão.

## Como manter estes registros

Atualizar a documentação quando uma decisão mudar. Registrar separadamente o que foi planejado, implementado e testado. Uma tarefa descrita aqui não significa uma entrega concluída. Prazos, responsabilidades e versões não confirmados devem permanecer como pendências.
